# 数据布局问题复盘：state/action 维度语义不一致

> 创建时间（北京时间）：2026-09-09 17:57

更新时间：2026-09-09

## 一句话结论

当前已发现并修正一个影响训练、归一化统计、离线评测和真机部署解释的历史问题：本地兼容代码曾把 split state 拼成 `[左6关节, 右6关节, 左爪, 右爪]`，但 action 数据是 `[左6关节, 左爪, 右6关节, 右爪]`。因此历史 delta action 的 state/action 对齐在语义上错位。

这意味着此前训练出来的 checkpoint 和离线 MSE 结果应标记为：

```text
legacy_joint12_grip2
```

它们可以作为历史记录和现象参考，但不应继续作为最终模型优劣判断。

## 数据实际布局

以 emptybox 470 数据为例，`meta/info.json` 中主要字段为：

```text
observation.state.joint: 12D = [left_joint_0..5, right_joint_0..5]
observation.gripper_position: 2D = [left_gripper, right_gripper]
actions: 14D = [left_joint_0..5, left_gripper, right_joint_0..5, right_gripper]
```

理论上，如果要合成 14D state，应为：

```text
[left_joint_0..5, left_gripper, right_joint_0..5, right_gripper]
```

但本地兼容代码实际做成了：

```text
[left_joint_0..5, right_joint_0..5, left_gripper, right_gripper]
```

## 问题来源

本地修改位置：

```text
world_action_model/datasets/wam_lerobot_dataset.py
scripts/compute_wam_task_norm.py
```

关键逻辑是为了兼容 LeRobot 数据列名：

```python
data_dict["action"] = data_dict["actions"]
data_dict["observation.state"] = np.concatenate([joint, grip], axis=-1)
```

这个修改解决了“字段名和 split state 读取”问题，但没有处理 action 的 6+1+6+1 排列，因此引入语义错位。

## 当前代码修正

2026-09-09 已把主代码路径改为 action-compatible state order：

```text
[left_joint_0..5, left_gripper, right_joint_0..5, right_gripper]
```

核心 helper：

```text
world_action_model/utils/action_layout.py
```

已修正的路径包括：

- `world_action_model/datasets/wam_lerobot_dataset.py`
- `scripts/compute_wam_task_norm.py`

验证结果：在真实 emptybox episode 第一帧上，修正后的右臂关节 action-state 平均绝对差约 `0.0047`，旧错位拼接约 `0.6745`；`compute_wam_task_norm.py` 的 strict alignment 检查已通过。

## 影响范围

受影响范围包括：

- `scripts/compute_wam_task_norm.py` 生成的 norm stats。
- `world_action_model/datasets/wam_lerobot_dataset.py` 训练数据读取。
- 使用相同拼接方式的 quick/eval/test 脚本。
- 依赖旧 norm/checkpoint 的离线 MSE 报告。
- 使用旧 checkpoint 的 GGUF / cpp 真机部署结果解释。

已完成训练和评测应统一视为 legacy 口径。

## 为什么不能直接修代码后复用旧 checkpoint

旧 checkpoint 学到的是旧 state 布局下的输入分布与 delta 目标。如果直接把 state 拼接顺序改正确，再加载旧 checkpoint，输入语义会变化，norm stats 也不匹配，结果不可直接对比。

正确做法是：

1. 修正 state 拼接为 `[L6, Lg, R6, Rg]`。
2. 重新计算 norm stats。
3. 用修正后的数据管线重新训练。
4. 用同一修正口径重新跑离线评测。
5. 新旧 checkpoint 分开命名，避免混用。

## 推荐的新命名

后续建议在 checkpoint、norm stats、GGUF、评测目录中加入布局标记：

```text
legacy_joint12_grip2      # 历史错位口径
aligned_l6g_r6g           # 修正后的 6+1+6+1 口径
```
